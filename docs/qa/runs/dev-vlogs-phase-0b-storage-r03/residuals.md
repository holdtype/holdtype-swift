## Debug-spike defect

The SSD preflight passed and the accepted wrapper completed its build stage,
but the hosted focused test could not launch. The wrapper confined the test
invocation to a fresh Foundation home without pinning the already-built
product lookup, so the test invocation searched a new default build-products
location. The wrapper emitted no success terminal.

The SSD cell is `fail`. It was not retried. The HDD cell is terminal
`not_available` in this serialized packet because the required stop after the
first-cell failure prevented its sole invocation. Its previously accepted
mechanics evidence is not reopened or restated as new runtime proof.

Residual class: `debug-spike defect`.

exit code to a Zsh read-only special variable. The wrapper exit status and
elapsed duration were therefore not retained. This does not change the closed
functional result: build success, focused-test failure, and zero wrapper
success terminals.

The initial process snapshot filter also matched its own filter process. The
single stored row proved to be only that filter; the observer was narrowed to
exact process names, the false row was removed, and the exact empty baseline
then matched the final process set. No process was terminated by this repair.

validated its exact run-owned identity, moved it exclusively to a fresh

object. The selected external scratch prefix was absent, so no external

The one continuously verified outer guard passed eleven identity/liveness
checks, was stopped with `TERM`, and was reaped exactly after initial evidence
serialization. The private raw evidence root and observer helpers were removed.
