# HoldType 1.0.13

This release fixes a critical recording-finalization issue affecting explicitly
selected microphones, including USB audio interfaces.

## Fixed

- HoldType waits for the audio file to finish before creating its recovery copy
  or sending it for transcription. Previously, an unfinished M4A could cause
  transcription to fail and leave an unreadable recovery copy.
- Completed recordings are checked with an audio decoder before recovery and
  upload. Unreadable recordings are preserved locally and are not uploaded.
- Missing completion callbacks fail within a bounded time instead of allowing
  an unfinished recording into transcription.
- Provider rejections retain their HTTP status, with clearer guidance for
  unavailable models, oversized recordings, and unsupported formats.
- Existing macOS settings using the previous standard `gpt-4o-transcribe`
  model move once to `gpt-transcribe`. Other custom models and later explicit
  choices are preserved.

## Added

- Optional writing-context hints in Transcription settings: Off, Automatic,
  and AI Tasks. Off remains the default. Automatic selects the AI Tasks hint
  when dictation starts in Codex; no app name or window content is sent.

Existing audio and API credentials are preserved. This update does not
automatically resubmit previous recordings or repair older incomplete copies.
